# Scientific basis

## Problem definition

Grammatical error correction (GEC) maps an observed Czech sentence `x` to a
corrected sentence `y`. CzechCore uses a conditional sequence-to-sequence model
to approximate:

```text
y* = argmax_y log P(y | x)
```

The unchanged sentence is included as a candidate. The runtime is therefore
allowed to conclude that no edit is better than an edit. This matters because
many Czech word forms are valid in one context and wrong in another.

CzechCore is not a formal proof system for Czech grammar. It combines a learned
sentence model with deterministic safety policy and exact text alignment.

## Czech linguistic phenomena

The acceptance suite covers representative examples from these families:

| Phenomenon | Why sentence context matters | Authoritative reference |
| --- | --- | --- |
| Subject-predicate agreement | Number, gender, animacy, and coordinated subjects determine participle endings | [ÚJČ: simple subject](https://prirucka.ujc.cas.cz/?id=600), [multiple subject](https://prirucka.ujc.cas.cz/?id=601) |
| `i/í` and `y/ý` | Lexical roots, morphology, and syntactic agreement can all determine spelling | [ÚJČ: i/y](https://m.prirucka.ujc.cas.cz/?id=103), [listed words](https://prirucka.ujc.cas.cz/?id=100) |
| `mě/mně` | Case determines the written form although pronunciation can coincide | [ÚJČ: forms of *já*](https://m.prirucka.ujc.cas.cz/?id=650) |
| Commas in complex sentences | Clause structure and subordinating conjunctions determine boundaries | [ÚJČ: commas in complex sentences](https://prirucka.ujc.cas.cz/?id=150) |
| Diacritics and spelling | Multiple character sequences can be valid words; local edit distance is insufficient | [Internetová jazyková příručka](https://prirucka.ujc.cas.cz/pda) |
| Repeated words | Exact adjacent repetition is mechanically detectable, but punctuation-separated rhetorical repetition must remain | CzechCore regression tests |

The ÚJČ rules are references for expected Czech, not hardcoded runtime rule
tables. Semantic corrections remain model-based. CzechCore uses regex only for
mechanical protection formats and exact adjacent repetition.

## Runtime model

The default model is
[`ufal/transformer-base-geccc-mate`](https://huggingface.co/ufal/transformer-base-geccc-mate),
published with *Refining Czech GEC: Insights from a Multi-Experiment Approach*.
It is a Czech encoder-decoder Transformer trained first with synthetic errors
generated by MATE and then fine-tuned on GECCC.

Runtime configuration read from the pinned model artifact:

| Property | Value |
| --- | ---: |
| Architecture | BART-style encoder-decoder Transformer |
| Parameters | approximately 60.8M |
| Encoder / decoder layers | 6 / 6 |
| Hidden dimension | 512 |
| Attention heads | 8 |
| Vocabulary | 32,000 WordPiece tokens |
| Maximum positions | 256 |
| Published GECCC F0.5 | 73.73 |

The model card reports this comparison:

| Model | Parameters | GECCC F0.5 |
| --- | ---: | ---: |
| Transformer base | 60.8M | 73.73 |
| ByT5 small | 300M | 72.56 |
| ByT5 base | 582M | 75.15 |
| ByT5 large | 1.275B | 77.01 |

The compact Transformer is the default Pareto choice: it exceeds ByT5-small in
the published metric while using roughly one fifth of its parameters. Larger
models remain possible teachers or quality profiles, not default device models.

## Training evidence

GECCC contains multiple Czech domains with different error densities and was
professionally annotated under a unified GEC scheme. The dataset paper reports
83,058 sentences and evaluates several Transformer baselines. See Náplava et al.,
[*Czech Grammar Error Correction with a Large and Diverse Corpus*](https://aclanthology.org/2022.tacl-1.26/),
TACL 2022, DOI `10.1162/tacl_a_00470`.

The newer MATE work reports a real-time synthetic generation pipeline covering
language-independent and Czech-specific errors. See Pechman et al.,
[*Refining Czech GEC: Insights from a Multi-Experiment Approach*](https://ufal.mff.cuni.cz/biblio/attachments/2025-straka-p1722258514738014790.pdf),
DOI `10.1007/978-3-032-02551-7_7`.

Published scores belong to those papers/models. They are not CzechCore acceptance
scores and are not reproduced by the 35-sentence repository suite.

## Tokenization and exact ranges

The model requires space-tokenized Czech input. CzechCore uses the same pinned
Czech UDPipe 1 model referenced by the UFAL implementation. UDPipe supplies
sentence segmentation, token forms, and `TokenRange=start:end` metadata. The
ranges count Unicode characters and allow CzechCore to map a generated sentence
back to exact spans in the original string.

Relevant primary documentation:

- [UDPipe API reference](https://ufal.mff.cuni.cz/udpipe/1/api-reference)
- [UDPipe user manual: preserving token ranges](https://ufal.mff.cuni.cz/node/1285)
- Straka and Straková,
  [*Tokenizing, POS Tagging, Lemmatizing and Parsing UD 2.0 with UDPipe*](https://ufal.mff.cuni.cz/biblio/attachments/2017-straka-m1614289952260637039.pdf)

## Candidate generation and confidence

The backend generates four deterministic beams. It also scores the unchanged
sentence. Duplicate strings keep their best score. For unique candidate scores
`s_i`, CzechCore reports a relative beam confidence:

```text
q_i = exp(s_i - max_j s_j) / sum_k exp(s_k - max_j s_j)
```

This quantity ranks the returned candidate set. It is **not** a calibrated
probability that the correction is objectively right. Consequently:

- suggestion mode can expose an edit without applying it;
- autocorrect is opt-in;
- the default `0.995` threshold is deliberately conservative;
- a production default must eventually be calibrated on a larger held-out
  Czech corpus with an explicit precision target.

## Safety policy

The neural candidate is rejected when:

- it changes a protected URL, email address, path, semantic version, or code-like
  literal;
- changed characters exceed 35% of the source sentence;
- relative beam confidence is below the suggestion floor;
- the encoded sentence exceeds 256 positions;
- autocorrect is requested but the candidate does not reach its threshold.

Accepted sentence edits are atomic. CzechCore never applies only part of one
neural rewrite.

## Alignment and edit classes

`difflib.SequenceMatcher(autojunk=False)` aligns the original and accepted
candidate. Non-equal opcodes become immutable, non-overlapping `TextEdit`
instances. Applying edits right-to-left reconstructs the candidate without
invalidating earlier offsets.

Classification is intentionally mechanical:

- whitespace-only changes -> `whitespace`;
- Unicode punctuation-only changes -> `punctuation`;
- equal strings after removing combining marks -> `diacritics`;
- equal strings after case folding -> `capitalization`;
- other contextual changes -> `grammar`.

`spelling` is reserved for future lexical evidence; it is not guessed from a
keyword list.

## Validity limits

- Sentence context is not document or paragraph semantics.
- A single reference can mark a valid alternative as wrong.
- Exact-match acceptance cases are not a representative corpus sample.
- Beam confidence is not calibrated correctness.
- Protected text increases precision by abstaining, which can lower recall.
- The current compact model misses at least one coordinated-subject example in
  the committed suite.
- The default assets are non-commercial; model replacement can change quality.
